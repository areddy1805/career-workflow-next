# Copilot UI

**Version:** 1.0.0
**Status:** Approved

---

## 1. Principles

Follows `docs/ui_v2/DESIGN_PRINCIPLES.md` (dark-first, keyboard-first, information density, progressive disclosure, explicit states, real-time freshness). New surfaces must satisfy the existing review checklist (a11y, empty/loading/error states, keyboard coverage).

## 2. Navigation & Page Hierarchy

New **"Copilot"** group in the sidebar (between Workflows and Intelligence):

```
Copilot
  Inbox         /copilot/inbox          (badge = pending count)
  Apply         /copilot/apply/:id      (Workspace wizard)
  Brief         /copilot/brief/:id
  Assistant     /copilot/assistant/:sessionId
  History       /copilot/history
  Analytics     /copilot/analytics
  Learning      /copilot/learning
  Settings      /copilot/settings
```

Routes are flat (matches current `App.tsx` pattern), pages default-export in `frontend/src/pages/copilot/`, command-palette entries auto-register.

## 3. Page Specifications

### 3.1 Inbox (`/copilot/inbox`)
- **Purpose**: unified triage of every normalized opportunity from all sources.
- **Layout**: toolbar (search, source filter, status filter, sort) + virtualized table (TanStack Table) → row click opens **Brief sheet** (upgrade of `JobDrawer`).
- **Row**: fit score, title, company, source badge, salary, effort chip, status, risk flag icon.
- **Actions**: `Apply` (→ workspace), `Skip`, `Dismiss`; keyboard: `1` brief, `a` apply, `s` skip, `d` dismiss, `j/k` move.
- **Empty/loading/error**: explicit states with CTA to ingest a source.

### 3.2 Application Workspace (`/copilot/apply/:id`) — the wizard
Steps (progress rail on left):
1. **Brief** — read-only summary, CTA "Begin".
2. **Answers** — all screening answers with status chips (auto/confirm/manual/locked); inline editing; `confirm all` bulk action.
3. **Resume** — recommended resume + reason; select alternative (AI/FDE).
4. **Assistant** — embedded panel (§3.4); form progress; checkpoints.
5. **Submit** — final review + **Submit button requiring deliberate gesture** (hold-to-confirm), then outcome.
Keyboard: `enter` advance, `space` confirm, `1-9` jump answer slots, `e` edit answer, `esc` back.

### 3.3 Brief view (`/copilot/brief/:id`)
Renders all 12 Brief sections (`05_APPLICATION_BRIEF.md`) as cards; verdict banner; provenance chips per section; "LLM-augmented" markers; CTA → apply. Collapsible "show only certain facts" mode.

### 3.4 Assistant panel (`/copilot/assistant/:sessionId`)
- Embedded live view of the controlled browser (video/iframe of Playwright page).
- Right rail: form field list with fill status (`filled/flagged/asked/unknown`), confidence bars, source chips.
- Checkpoint banner with exact reason; `Continue`, `Edit field`, `Take over` buttons.
- **Take over** switches to human control (assistant annotates; never fights back).
- Live audit feed of assistant actions.

### 3.5 History (`/copilot/history`)
Table of all sessions: opportunity, company, strategy, outcome, times (started/submitted/response/interview/offer), effort saved; row → session timeline (reconciles status view ADR-012).

### 3.6 Analytics (`/copilot/analytics`)
- Funnel: ingested→briefed→applied→viewed→shortlisted→interview→offer.
- Response/conversion rates by provider, ATS, resume profile, source.
- **Effort saved**: cumulative minutes saved (est. manual − assisted).
- Answer Bank health: auto-resolve rate, correction rate, LLM call trend.
- Learning calibration: predicted vs actual interview probability.

### 3.7 Learning (`/copilot/learning`)
- Answer Bank editor (search by canonical label; filter by status; confirm/lock/edit per profile).
- Profile switcher (AI/FDE/generic) with atomic namespace swap.
- Evidence viewer (`CANDIDATE_EVIDENCE` read-only) + signals overview.
- Ranking bias view (persisted `learning_bias` contributions).

### 3.8 Settings (`/copilot/settings`)
Profiles, confidence thresholds (mirror `04_BROWSER_ASSISTANT.md` §6), autopilot toggle (off by default, per-session), source enablement, effort caps, LLM budget usage.

## 4. Keyboard-First & Accessibility

- Full navigation via keyboard; every action has a shortcut; shortcuts shown in tooltips.
- WCAG AA in both themes; focus rings; ARIA on all interactive elements.
- Workspace wizard is fully operable without mouse (radio/checkbox answer confirm via space).
- Existing `StatusBadge`, `RelativeTime`, `Sheet`, `ResizablePanelGroup` reused; new shared components only where justified.

## 5. State & Data

- Server state: TanStack Query hooks (`useCopilotOpportunities`, `useBrief`, `useSession`, `useAnswers`, `useAssistant`, …) in `frontend/src/lib/hooks.ts`; endpoint modules in `frontend/src/lib/api/copilot.ts`.
- Workspace client state: Zustand store `frontend/src/store/copilot.ts` (current step, answers view, assistant view).
- Polling: inbox 30s, session 1s while active, assistant 1s while filling, analytics 30s.
