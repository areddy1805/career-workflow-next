# ADR-012: Lifecycle Reconciliation via Read View

**Status:** ✅ Frozen
**Date:** 2026-08-02
**Supersedes:** None

## Context

Five overlapping state machines exist (pipeline opportunity status, workflow queue status, employer funnel stage, canonical JobLifecycleStore, ledger free-form status). The Copilot UI must present one coherent status.

## Decision

The Copilot maintains a **read-only `status_view`** reconciled from `JobLifecycleStore` (canonical) + `WorkflowQueue` (pre-submit) + ledger `lifecycle_stage` (post-submit). Canonical lifecycle wins; conflicts resolved by a frozen mapping table in `oppstore/status_view.py`.

## Alternatives Considered

- New 6th state machine written by Copilot — rejected: adds ownership ambiguity.
- Show raw multi-status — rejected: confusing UX.

## Tradeoffs

- **Gained:** one truthful status; no new pipeline mutations.
- **Sacrificed:** tiny reconciliation cost per read (cached).

## Consequences

- Reconciliation matrix has explicit tests.
- Pipeline DBs remain authoritative.
