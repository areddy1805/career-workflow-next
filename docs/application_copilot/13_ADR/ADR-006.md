# ADR-006: Single-User v1, SaaS-Ready Design

**Status:** ✅ Frozen
**Date:** 2026-08-02
**Supersedes:** None

## Context

Multi-tenant (auth, per-user DB, onboarding, security) multiplies v1 scope.

## Decision

v1 is **single-user local**, but the design is SaaS-ready: profile switching is a first-class concept, subsystems are API-shaped, and the persistence layer separates per-profile namespaces so multi-tenancy is additive later.

## Alternatives Considered

- Multi-user from day one — rejected: scope.
- Personal-tool-only (no platform ambition) — rejected: the evidence/answer/learning stack is inherently reusable across users.

## Tradeoffs

- **Gained:** speed to value; future platform path.
- **Sacrificed:** no cloud/auth in v1 (accepted non-goal).

## Consequences

- `copilot_answers` keyed by `(question_fp, profile_id)` — tenant-extension ready.
- No auth/CORS hardening is a v1 non-goal; flagged in security review (CP-9-02).
