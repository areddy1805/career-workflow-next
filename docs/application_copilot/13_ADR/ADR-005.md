# ADR-005: Source-Agnostic Browser Assistant on the Normalized Model

**Status:** ✅ Frozen
**Date:** 2026-08-02
**Supersedes:** None
**Related:** ADR-004

## Context

The assistant must not be a pile of per-provider scripts that rot as providers change.

## Decision

Every source normalizes into ONE `CopilotOpportunity`. The assistant operates **only** on the normalized opportunity (fields + apply_url + strategy). ATS-specific adapters (Greenhouse/Lever/Ashby) are **optimizations, not architectural dependencies** — if an adapter is missing or stale, generic extraction still works.

## Alternatives Considered

- Provider-specific assistants — rejected: tight coupling, unbounded maintenance.
- Assistant reading raw source payloads — rejected: duplicates normalization logic in the UI/agent layer.

## Tradeoffs

- **Gained:** durability, single code path, testability.
- **Sacrificed:** some per-provider polish unless adapters added.

## Consequences

- `ingestion/` owns normalization; `browser/` owns execution.
- Adapters are optional, cached, versioned.
- Fixtures guarantee generic fallback correctness.
