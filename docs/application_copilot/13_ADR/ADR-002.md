# ADR-002: Assist-First, Human-Submit Execution Model

**Status:** ✅ Frozen
**Date:** 2026-08-02
**Supersedes:** None
**Related:** ADR-001, ADR-005

## Context

Submission is the point of highest consequence and highest risk (ToS, ban, wrong-application). The mechanism had to be settled before architecture.

## Decision

The Browser Assistant is read-only until final submit. Submission requires a deliberate human gesture (hold-to-confirm) — except when the user explicitly opts into per-session autopilot (deferred to v5.2.0). No blind clicks, no automated retries after rejection.

## Alternatives Considered

- Fully autonomous submit — rejected (ADR-001).
- Submit on confidence ≥ threshold without gesture — rejected: removes the human authority and creates ban risk.

## Tradeoffs

- **Gained:** safety, trust, auditability, no ban risk.
- **Sacrificed:** unattended operation.

## Consequences

- `safety.py` enforces the read-only-until-submit invariant.
- Every browser action audited (`copilot_browser_actions`).
- Checkpoints before upload, sensitive fields, and submit.
