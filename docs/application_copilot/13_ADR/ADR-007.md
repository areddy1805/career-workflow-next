# ADR-007: Copilot ↔ Pipeline Decoupling (Read-Only + Repo-API Writes)

**Status:** ✅ Frozen
**Date:** 2026-08-02
**Supersedes:** None

## Context

The production pipeline is architecturally frozen and accounting-critical. The Copilot must not endanger it.

## Decision

The Copilot **reads** the pipeline through stable interfaces (OpportunityRepository, JobLifecycleStore, WorkflowQueue, CandidateIntelligence, ResumeRouter, ResumeDeltaEngine, PriorityEngine, HybridQuestionResolver, InferenceEngine, JobDecisionLedger). It **writes pipeline-visible outcomes only through existing repository/queue APIs** (`WorkflowQueue.transition` etc.). It never mutates pipeline DBs directly and never re-implements pipeline logic.

## Alternatives Considered

- Direct DB writes — rejected: accounting/regression risk.
- Full event-bus decoupling — rejected: over-engineering for v1 single-user.

## Tradeoffs

- **Gained:** pipeline safety, accounting integrity, reversible outcomes.
- **Sacrificed:** atomic cross-DB transactions (acceptable — outcomes are idempotent).

## Consequences

- Ledger-consistency regression tests are mandatory (CP-4-04, CP-9-01).
- `copilot.db` facts that mirror pipeline facts are derived caches with `synced_from`.
