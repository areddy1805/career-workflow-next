## Cross-cutting observations

- **Data dependencies**: every page is react-query-driven; polling cadence varies 1s–30s. No optimistic updates anywhere; mutations invalidate only the pipeline query.
- **Loading states**: four distinct idioms coexist — (a) `animate-pulse` skeleton blocks (Dashboard), (b) full-overlay backdrop-blur pill (Ledger), (c) inline pulse text (Pipeline), (d) spinner rows (Jobs). No shared loading primitive.
- **Empty states**: dashed-border message (Dashboard funnel), icon+2-line (Ledger), log placeholder (Pipeline), table "No jobs found" — three different visual languages, no shared EmptyState component.
- **Error states**: inline red text (Pipeline), sheet fallback (Ledger), silent (Dashboard/Runs/metrics pages rely on query error → empty). No error boundary per page (only global).
- **Destructive operations**: Pipeline live run (ConfirmDialog) is the only guarded mutation; queue transitions and copilot live-browser actions have no confirmation.
- **Primary CTAs by page**: launch run (Pipeline), apply (copilot wizard), queue triage (Applications/Inbox), everything else read-only inspection — the console is 70% observation, 30% action. Design must give observation surfaces maximum legibility and action surfaces maximum confidence.
- **IA tension**: `/metrics` (pipeline analytics) vs `/copilot/analytics` (copilot analytics); `/intelligence` (search intel) vs `/explorer` (run artifacts); Diagnostics group has 4 pages with thin content (Audit/Developer/Logs/System overlap in purpose).
